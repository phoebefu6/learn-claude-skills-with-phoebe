Part 0

Why this session exists

Most people use Claude like a very good chat box. The people who get 10x out of it use skills: reusable instruction packs Claude loads only when a task needs them. Skills do two things at once - they make a workflow drastically better, and they spend fewer tokens doing it, because a skill's detail stays on disk until the moment it fires. This session teaches the mechanic behind that, the token budget it protects, and the 8 skills that form the core stack for all 17 tracks in this course.

Part 1 · covers "Agent Skills with Anthropic" + "Introduction to Agent Skills"

What a skill actually is 7 min live

A skill is a folder with a SKILL.md file: a name, a one-line description, and a body of instructions - plus optional scripts and reference files. Instead of re-explaining a workflow every time, you package it once, and Claude applies it automatically when a task matches. The genius is progressive disclosure: Claude reads the cheap part always, and the expensive part only when it commits to the job.

LiveThe anatomy of a SKILL.md2 min▶

Every skill is just markdown with a little front matter. The two lines that matter most are name and description - they are all Claude reads to decide whether to open a skill, so they double as the trigger.

  • name - what to invoke (grilling, impeccable, course-builder).
  • description - "use when..." phrasing packed with the words a matching task would contain. A vague description means the skill never fires.
  • body - the actual instructions, checklists, and rules, loaded only when triggered.
  • bundled files - references, templates, scripts the body points to, loaded only when a step needs them.
★ Try it nowExplain the difference between a skill and just pasting instructions into chat. In your answer, cover: what gets reused, what gets loaded when, and why 50 installed skills don't slow Claude down.
Real world

The re-explaining tax. A team kept pasting their 400-word report format into every chat - paying for it every single time. Packaged as one skill, Claude now applies the format on the phrase "weekly report", and the 400 words load once, only when relevant. Same output, a fraction of the tokens, zero copy-paste.

LiveWhere skills live: Claude.ai, Code, API, the SDK2 min▶

The same skill format runs across the whole Claude surface - this is why learning it once pays everywhere:

Skills also compose with MCP (external tools/data) and subagents (fresh-context helpers) - the combination is where complex workflows come from, and it recurs in every later session.

Self-studySkill vs Project vs prompt - when to use which2 min read▶
  • Prompt - a one-off. Great for a task you won't repeat.
  • Project / CLAUDE.md - standing context for a workspace ("we are a retail company, our stack is X"). Loaded for every conversation there.
  • Skill - a repeatable job with its own trigger, portable across projects and surfaces, loaded only when it fires.

Rule of thumb: if you have explained the same how-to more than twice, it wants to be a skill. Session 8 turns one of your own repeated jobs into a skill live.

Part 2 · covers "AI Engineering with Claude" context strategies

The token economy of a session 6 min live

Every conversation has a fixed context window - think of it as the working memory and the meter. Everything competes for that space: system rules, your files, skill bodies, and the growing back-and-forth. Once you can see the budget, "minimum token consumption" stops being a slogan and becomes a set of moves.

LiveWhat actually eats your context2 min▶

Four claimants, in the order they usually balloon:

  • The conversation itself - long threads carry every earlier turn forward. The #1 silent cost.
  • Dumped files - pasting a 300-page PDF to ask one question pays for all 300 pages.
  • Verbose output - Claude narrating its whole plan every turn.
  • Tool results - a raw search or big file read lands in full unless something summarizes it.
The one-line reframe Don't ask "how do I prompt this?" Ask "what is the smallest amount of context that lets Claude get this right?" Every Core Stack skill is an answer to that question.
LiveThe five token-saving moves2 min▶

Everything in this course reduces to five moves. Memorize these; the Core 8 skills automate them.

MoveWhat it doesSkill that does it
Don't load itKeep detail on disk until neededskills (progressive disclosure)
Offload itSend heavy work to a fresh-context helpersubagents, Explore
Compress itReturn conclusions, not raw dumpscaveman, deep-research
Get it right onceAvoid the rework loop entirelygrilling, verification
Reuse itCache stable context across callsProjects, prompt caching (S4)

Self-studyWhy rework is the biggest token sink of all1 min read▶

The most expensive tokens are the ones you spend building the wrong thing. A build that goes three rounds because the goal was fuzzy costs far more than the thirty seconds of questions that would have pinned it down. This is why grilling sits first in the Core Stack: getting it right once is the single largest saving available, and it is free.

Part 3 · the stack every later session builds on

The Core 8 skills 8 min live

Eight skills that apply no matter which of the 17 tracks you're working in. They map onto four phases of any real task - plan, offload, compress, ship - and each one is a token-saving move made automatic.

LivePLAN - grilling, brainstorming, using-superpowers2 min▶
  • grilling (a.k.a. grill-me) - stress-tests your plan with hard questions before a line is built. Kills the rework loop, which is the biggest token sink there is. Trigger it on any "let's build X".
  • brainstorming (superpowers) - shapes a fuzzy idea into a clear spec before plan mode. Grill and brainstorm are the "get it right once" move.
  • using-superpowers - the router: it forces "is there a skill for this?" before acting, so you use the specialist instead of improvising. Prevents the most common waste - reinventing a job a skill already does.
Real world

This very course started with a grill: audience, spine, learn-first, name - four questions, answered before any HTML existed. That is why there was no rebuild. Thirty seconds of grilling saved a session's worth of tokens.

LiveOFFLOAD - subagents & Explore / deep-research2 min▶

The highest-leverage token move on any big task: don't do the heavy reading in your main thread - send it to a helper with its own budget that returns only the conclusion.

  • subagent-driven-development / dispatching-parallel-agents - fan work out to fresh-context agents. Your main context stays lean; agents can even run in parallel.
  • Explore - read-only search agent for "where is X / how is Y done" across many files. Returns the answer, not the file dumps.
  • deep-research - multi-source web research with adversarial verification, returned as a cited summary.
★ Try it nowUse a subagent to answer this without loading it all into our main chat: [a question that needs reading many files or pages]. Return just the conclusion and the 3 sources you used.
Real world

Mapping a 40-file codebase inline can burn your whole window before you've learned anything. One Explore agent reads the excerpts and hands back a file:line map - the main thread spends a fraction of the tokens and keeps room to actually work.

LiveCOMPRESS - caveman & cavecrew2 min▶
  • caveman-compress - strips articles, filler, and pleasantries from output while keeping every technical fact and all code intact. Terse by default (this whole session was built in caveman mode).
  • cavecrew-investigator - a read-only code locator whose output is compressed so the main thread eats roughly 60% fewer tokens than a vanilla search.
  • cavecrew-reviewer - one line per finding, severity-tagged, no praise, no padding.
When NOT to compress Caveman auto-drops for security warnings, irreversible-action confirmations, and multi-step instructions where fragment order could be misread. Compression is for volume, never for clarity where a mistake is costly.
LiveSHIP - verification-before-completion & impeccable2 min▶
  • verification-before-completion (superpowers) - blocks the false "done". It forces a real check - tests run, links resolve, the thing actually works - before anyone says finished. Rework caught here is far cheaper than rework caught by your audience.
  • impeccable (~15k★) - the taste + anti-slop gate on anything visual. It raises craft within a locked brand; it never overrides your palette or fonts. Every design/deck/page output passes through it.
Real world

"Looks done" and "is done" are different claims. A page that renders in your editor can still 404 its stylesheet in the browser. Verification is the habit that turns "should work" into "I watched it work" - and it protects your name the way diligence protected nobody in the Avianca case.

Demo 1 of 3

Grill-first on a real task ★ 6 min · follow along

The cheapest token you ever spend is a question asked before building. Run the grill on a task from your actual week and watch how much rework it removes.

★ The grill triggerBefore you build anything, grill me on this: [describe the thing you want - a script, a deck, a report, a plan]. Ask me the 3-5 hardest questions whose answers would change what you build - audience, scope, format, the constraint I haven't mentioned. Do not start until I've answered.

Pick a real task you were about to hand Claude cold.

Run the grill trigger. Answer honestly - notice which question you hadn't thought about.

Let it build only after the questions are answered. Compare mentally to the version you'd have gotten from a one-line ask.

Save the good questions - they become your own reusable grill for that kind of task.

Why this is a token move A three-round rebuild costs many times what five questions cost. Grill-first is "get it right once" - the largest free saving in the whole stack.
Demo 2 of 3

Offload to a subagent ★ 7 min · build your own

Feel the difference between reading everything yourself and sending a helper to do it. This is the offload move, done rather than described.

Find a question that needs reading a lot - a folder of files, several web pages, a long doc.

Ask Claude to answer it inline first. Watch the context fill with raw material.

Now start fresh and use the subagent prompt below. The helper reads; you get the conclusion.

Notice the main thread stayed lean - room left to actually act on the answer.

Subagent offload promptDispatch a subagent to investigate this and report back only the conclusion plus a short evidence list - keep the raw material out of our main conversation: [the question - e.g. "which files define our auth flow and what calls them", or "compare these 4 vendor docs on pricing"] Return: a 5-bullet answer and the sources/files used. No full dumps.
Real world

Building this course, Sessions 2-8 were written by parallel subagents, each reading Session 1 as the template and returning finished pages. The main thread never held all eight in memory at once - that's the offload move at course scale.
