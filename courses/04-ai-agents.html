Part 1 · covers Prompt Engineering Interactive Tutorial + API Fundamentals

The prompt + API foundation 7 min live

Everything an AI app does starts with one API call carrying one prompt. Two skills own this layer: prompt-master for how you construct the prompt, and claude-api for everything about the call itself - model ids, pricing, parameters, streaming, tool use, MCP, prompt caching, token counting. If you only remember one skill from this session, remember that claude-api is where the literal token-cost knowledge lives, so you never answer pricing or limits from memory.

Liveprompt-master - construct, don't improvise2 min▶

prompt-master gives you the construction patterns instead of a blank box: role and task up front, context and examples in the middle, output format pinned at the end, and the reasoning space the model needs to get it right. Reach for it whenever a prompt is going into production or being reused - a one-off chat message doesn't need it, but anything a skill or app will send a thousand times does.

  • Structure - clear task, relevant context, concrete examples, explicit output shape.
  • When - production prompts, system prompts, anything reused or evaluated.
  • Token effect - a precise prompt gets it right on the first call, killing the retry-and-rephrase loop that quietly doubles cost.
★ Try it nowUse prompt-master to turn this rough ask into a production-grade prompt: [paste a rough instruction]. Show the structured version and name what each block is doing.
Real world

The rephrase tax. A support bot with a vague prompt answered off-topic one time in five, and each miss meant a re-ask. A structured prompt-master rewrite cut the miss rate sharply - fewer calls, lower bill, same model. The prompt, not the model, was the cost.

claude-api is the skill you open before answering anything about the model itself. It carries the knowledge that changes month to month and must not be guessed:

Reach for it whenever the task names Claude, Opus, Sonnet, Haiku, the SDK, pricing, or limits. The rule is simple: never answer model facts from memory - open the reference, because the numbers move.

Why this is the token skill Token counting and pricing live here, so this is literally where "minimum token consumption" gets measured. You can't optimize a cost you can't see, and this skill is how you see it.
Self-studyAnatomy of a strong API call2 min read▶
  • System prompt - stable rules and role. Put it first so caching can reuse it.
  • Context block - the documents or data, also cacheable if stable.
  • Messages - the actual turn, the small variable tail.
  • Tools - definitions the model may call; results return as structured data, not prose.
  • Params - max tokens caps the output cost; streaming changes delivery, not price.

Order matters for cost: stable-and-expensive first, variable-and-small last. That single layout choice is what makes prompt caching pay off.

Part 2 · covers Tool Use + Real World Prompting

Make Claude do office work 6 min live

A huge share of real work is a document: a Word report, a PowerPoint deck, an Excel model, a PDF to read. The anthropic-skills family gives Claude first-class handling of all four, and dedicated MCP servers add live app control. The move here is picking the right content type and letting the matching skill own the file format.

LiveThe document skills: docx, pptx, xlsx, pdf2 min▶

Each of these is triggered the moment its file type is involved - as input, output, or both. You don't describe a format; you name the deliverable and the skill handles the machinery.

  • docx - generate a formatted Word report, or read one to summarize.
  • pptx - build a deck with real layouts and speaker notes, or extract slide text.
  • xlsx - create a spreadsheet with formulas, or read a model to analyze it.
  • pdf - parse, fill, merge, or split PDFs.
★ Try it nowTake these five bullet findings and produce a two-page Word report with a title, an executive summary, and a findings table: [paste five bullets].
LiveThe PowerPoint and Word MCP servers2 min▶

When the skill format isn't enough - you want Claude to open, edit, and export a live file through the actual application - the PowerPoint MCP and Word MCP servers expose that as tools: add a slide, set a title, insert an image, export a PDF; create a document, format text, replace text, save.

Rule of thumb: reach for the skill to author a file from content, and the MCP server when you need step-by-step control of the app itself. Both return structured results, not prose narration, which keeps the token cost of each step small.

Real world

A weekly board deck used to be a manual copy-paste from a doc into slides. Wired through the PowerPoint MCP, the numbers flow from the source file into the template in one pass - the human reviews, doesn't rebuild.

Self-studynotebooklm - turn a corpus into a study brief1 min read▶

notebooklm takes a pile of source documents and turns them into a grounded, navigable brief - useful when you're onboarding to a topic and want a synthesized read rather than raw files in your context. It's the "understand this stack of docs" companion to the format skills above, and it keeps the heavy reading out of your main window.

Part 3 · covers Prompt Evaluations + skill authoring

Skills that build skills + live artifacts 6 min live

The most leveraged thing you can build with Claude is a new skill - a reusable job that then loads only when it fires. skill-creator and writing-skills teach the discipline of authoring one, and artifact-capabilities takes a published page from a static snapshot to something that reads live data, holds shared state, or updates itself.

Liveskill-creator - and why the description is everything2 min▶

anthropic-skills:skill-creator creates, edits, and evaluates skills. It scaffolds the folder and SKILL.md, but its most important job is optimizing the description - because the description is the trigger. A skill with a vague description never fires; a skill with a description packed with the words a matching task would contain fires reliably.

  • Create - scaffold name, description, body, and bundled files.
  • Tune the trigger - the description is what Claude reads to decide whether to open the skill, so it is where you spend your effort.
  • Eval - test that the skill fires on the right prompts and not the wrong ones.
The trigger is the product A brilliant skill body is worthless if the description never matches real tasks. skill-creator's description optimization is the single highest-value step in authoring - it decides whether the skill is ever used.
Livewriting-skills - the authoring discipline2 min▶

superpowers:writing-skills is the craft layer on top of scaffolding: how to write a skill that is tight, unambiguous, and progressive-disclosure friendly. Keep the always-loaded part small, push detail into reference files the body points to, and write instructions the way you'd brief a capable colleague.

  • Small front, deep back - name and description stay tiny; heavy reference lives in bundled files loaded only when a step needs them.
  • One job per skill - a skill that tries to do everything triggers on nothing cleanly.
  • Token effect - disciplined authoring is what makes 50 installed skills cost almost nothing until one fires.
Self-studyartifact-capabilities - live, stateful, self-updating pages2 min read▶

A published artifact is normally a static snapshot. artifact-capabilities declares the runtime behavior a page is granted so it can do more:

  • Read live or connected data - the page shows fresh numbers, not a frozen copy.
  • Hold shared state - viewers see the same evolving data.
  • Self-update - the page can republish itself.

Load this skill's roster before declaring any capability - it tells you what's available and how to call it. The default is still static (cheapest and instant); you add capabilities only when the page genuinely needs to stay live.

Part 4 · the cost model for AI apps

Token discipline for AI apps 3 min live

At app scale a small per-call waste multiplies into a real bill. Three moves from this session are the levers you pull, and each one is a concrete answer to "what is the smallest context that gets this right?"

LiveThe three levers, spelled out2 min▶
  • Prompt caching - place the stable, expensive context first so it is billed once and reused. This is the reuse move from Session 1, made concrete at the API level.
  • Structured tool output - define tools that return JSON. A tool that returns clean fields costs far less than one that narrates a paragraph, and it's easier to act on.
  • RAG over stuffing - retrieve the handful of relevant chunks for a question instead of loading the entire corpus into every call. The corpus lives in a store; only the relevant slice enters the window.
The AI-app reframe Don't ask "how big a model do I need?" Ask "what is the smallest context that gets this call right, and how do I stop paying for it twice?" Caching, structured output, and RAG are the three answers.
Self-studyWhy stuffing the corpus is the classic trap1 min read▶

It's tempting to paste an entire knowledge base into the prompt "so the model has everything". You pay for all of it on every call, the model's attention is diluted across mostly-irrelevant text, and answers get worse, not better. RAG flips it: a retrieval step finds the few chunks that actually bear on the question, and only those enter the window. Smaller context, sharper answer, lower bill - the token-saving and the quality win point the same direction.

Write a prompt, then measure it ★ 6 min · follow along

Construction plus measurement is the whole discipline. Use prompt-master to build a prompt, then run a tiny eval so you have a number, not a vibe.

★ The build-then-measure triggerUse prompt-master to write a production prompt for this task: [describe the task]. Then set up a tiny Prompt Evaluations run: give me 3 test inputs, the expected behaviour for each, and a pass/fail check. Report which passed.

Pick a prompt you'll reuse - a classifier, a summarizer, a formatter.

Build it with prompt-master; note the structure it imposes.

Write three test inputs with expected outputs and run the eval.

Tweak the prompt, re-run, and watch the pass rate move - now you're engineering, not guessing.

Real world

A team argued for a week about two prompt phrasings. A ten-input eval settled it in minutes and showed both were beaten by a third nobody had tried. The measurement, not the debate, found the answer.

Three questions before you go 🎯 ◐ 90 seconds

1 · What does prompt caching actually save you?

Put the stable, expensive context first; caching reuses it so big fixed context isn't reprocessed at full cost on every call.

2 · When authoring a skill with skill-creator, the highest-value step is...

3 · For a question over a big knowledge base, the token-efficient move is...

Stuffing pays for the whole corpus on every call and dilutes attention. RAG loads only the relevant slice - smaller context, sharper answer.
